# Смены — прибыль и зарплата

Веб-приложение для учёта прибыли и зарплат сотрудников **без открытия смен**: прибыль приходит сама через расширение для Chrome, оклад начисляется каждый рабочий день, аналитика показывает, в какие часы работа приносит больше всего. Работает в браузере, удобно на телефоне (можно добавить на главный экран как приложение).

**Как считается зарплата.** За день сотрудник получает: оклад в день (капает в течение дня, к полуночи — полностью) + процент от **каждого** поступления прибыли + бонусы − штрафы ± ручные правки администратора. Схему оплаты задают две галочки: «фиксированный оклад» и «% с прибыли» — можно включить одну или обе. Процент фиксируется в момент поступления, оклад хранится с историей («новый оклад действует с …»), поэтому изменение ставок не переписывает прошлое. В выходные по графику, отгулы, больничные и отпуск оклад не начисляется. Баланс «к выплате» = всё начисленное − выплаты.

**Сотрудник**
- главная: «капающий» заработок за сегодня, прибыль и дневная цель, баланс к выплате, лента всех изменений прибыли;
- быстрый ручной ввод прибыли (наличные, переводы) с отменой в течение 15 минут;
- заработок по дням: оклад, %, бонусы, штрафы, выплаты;
- аналитика: выводы простыми словами, сравнение с прошлым периодом, прибыль по дням и дням недели, самое прибыльное время, карта «день недели × час», рейтинг КПД команды с местом, баллом и значками, серия дней с прибылью 🔥;
- аванс: заявка на часть уже заработанного, её можно отменить, пока не рассмотрена; после одобрения сумма вычитается из зарплаты;
- свой график смен на месяц (только просмотр);
- уведомления: выплаты, бонусы, штрафы, «дневная цель выполнена», напоминание о дне зарплаты.

**Администратор**
- обзор в реальном времени: кто сейчас работает (открыта рабочая страница), у кого давно нет прибыли, прибыль команды против цели, прогноз до конца месяца;
- аналитика по команде и по каждому: прибыль против зарплат и «чистыми», маржа, изменения к прошлому периоду, выводы словами, дни недели, лучшее время, тепловая карта, вклад каждого;
- рейтинг КПД: балл 0–100 (прибыль за рабочий день, отдача на зарплату, прибыль в активный час, стабильность), пьедестал и значки;
- журнал поступлений: каждое изменение прибыли с источником (расширение / вручную / админ), правка, удаление, выгрузка в CSV;
- зарплата: ведомость за период, выплаты с уведомлением, бонусы и штрафы, ручная правка суммы к выплате (с историей и причиной), заявки на аванс (одобрить/отклонить, журнал с отменёнными заявками), выгрузка ведомости в CSV для Excel;
- график смен: календарь на месяц, несколько дней выделяются зажатием и свайпом, диапазон «с … по …» и чередования 2/2, 3/3, 5/2, через день, сутки/двое;
- сотрудники: схема оплаты (оклад и/или %), оклад в день, % от прибыли, график рабочих дней, дата начала начислений, дневная цель;
- настройки: часовой пояс, цель команды на день, длина «лучшего окна», порог простоя; резервная копия базы.

Все суммы ведутся в сомах (KGS). Старые закрытые смены при обновлении перенесены в журнал поступлений вместе с заработанной по ним ставкой.

## Расширение для Chrome

Папка `extension/` (её же можно скачать архивом из приложения: «Профиль → Расширение»).

1. Распакуйте архив, откройте `chrome://extensions`, включите «Режим разработчика» → «Загрузить распакованное» → выберите папку.
2. В приложении: «Профиль → Расширение → Получите код подключения», вставьте код в окно расширения.
3. Откройте рабочий сайт, нажмите в расширении «Выбрать сумму на этой странице» и кликните по сумме прибыли.

Дальше расширение само следит за суммой и отправляет каждое изменение. Режимы: «общая сумма — считать прирост» (по умолчанию) или «каждое новое число — отдельная прибыль». Защита от ложных срабатываний: рост засчитывается, когда держится 1,5 с, уменьшение — через 15 с и считается сбросом счётчика (новый отсчёт, без минуса). Если связи нет, показания копятся в очереди и отправляются позже. Пока рабочая страница открыта, администратор видит сотрудника «онлайн».

Расширение входит по личному токену (хранится на сервере только в виде хеша), его можно отключить в профиле.

## Технологии

- Сервер: Node.js 22.13+ (Express 5), встроенный модуль `node:sqlite` — без нативных зависимостей.
- База: SQLite-файл в каталоге `DATA_DIR` (на Railway — Volume). Режим WAL + `synchronous=FULL`: подтверждённая запись уже на диске.
- Клиент: React + Vite, интерфейс на русском, адаптивный (нижнее меню на телефоне, верхнее на компьютере), тёмная тема по настройке системы.
- Пароли: `scrypt` с солью. Сессии: JWT в cookie `httpOnly` с `SameSite=Lax`, срок 30 дней с продлением. При смене пароля, блокировке или удалении сотрудника все его сессии сразу становятся недействительными.
- Защита входа от перебора: не больше 10 неудачных попыток за 15 минут с одного IP.

## Локальный запуск

Нужен Node.js 22.13 или новее.

```bash
npm install && npm run dev
```

Откройте http://localhost:5173. При первом запуске без настроек создаётся администратор **admin / admin12345** (только локально, в production такой учётки не будет). База появится в папке `./data`.

Чтобы задать своего администратора, скопируйте `.env.example` в `.env` и поменяйте значения.

Запуск в «боевом» режиме локально (сборка + один сервер на http://localhost:3000):

```bash
npm run local
```

## Деплой на Railway

### 1. Залить код на GitHub

Репозиторий уже инициализирован и в нём есть первый коммит. Создайте пустой репозиторий на GitHub и выполните:

```bash
git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
```

```bash
git push -u origin main
```

### 2. Создать сервис

1. На [railway.com](https://railway.com) → **New Project** → **Deploy from GitHub repo** → выберите репозиторий.
2. Railway сам найдёт `railway.toml` и `Dockerfile`: сборка через Docker, healthcheck по адресу `/api/health`.

Первый деплой без Volume специально завершится ошибкой: приложение не стартует на Railway без постоянного хранилища, чтобы вы случайно не потеряли данные. Это нормально, переходите к следующему шагу.

### 3. Подключить Volume (обязательно)

1. Откройте сервис → правый клик по нему на схеме проекта (или **Command Palette** ⌘K / Ctrl+K) → **Attach Volume** / **Create Volume**.
2. **Mount path:** `/data`.
3. Размера по умолчанию хватит надолго: база с годами работы занимает единицы мегабайт.

### 4. Задать переменные окружения

Сервис → вкладка **Variables**:

| Переменная | Значение | Обязательно |
|---|---|---|
| `DATA_DIR` | `/data` (тот же путь, что mount path Volume) | да |
| `ADMIN_LOGIN` | логин первого администратора, например `boss` | да |
| `ADMIN_PASSWORD` | надёжный пароль, не короче 8 символов | да |
| `ADMIN_NAME` | имя администратора | нет |
| `SESSION_SECRET` | случайная строка от 32 символов | нет (иначе создаётся сама и хранится на Volume) |
| `BACKUP_INTERVAL_HOURS` | как часто делать копию, по умолчанию `24` | нет |
| `BACKUP_KEEP` | сколько копий хранить, по умолчанию `14` | нет |

`PORT` задаёт сам Railway, трогать его не нужно.

После сохранения переменных Railway пересоберёт сервис. В логах должно появиться:

```
[db] применена миграция 1_initial
[auth] создан администратор «boss»
[server] http://localhost:8080  (данные: /data)
```

### 5. Открыть приложение

Сервис → **Settings** → **Networking** → **Generate Domain**. По этой ссылке входите под администратором и создавайте сотрудников во вкладке «Сотрудники». Ссылку и логины раздайте операторам. На телефоне можно открыть меню браузера и выбрать «На экран "Домой"».

### Обновления

Достаточно `git push` в ветку `main`: Railway пересоберёт и перезапустит сервис. База лежит на Volume и при редеплое не затрагивается. Новые миграции применяются автоматически при запуске. Каждая выполняется в транзакции и не трогает существующие данные.

## Сохранность данных

- База — один файл `DATA_DIR/app.db` на Railway Volume. Volume переживает редеплой, перезапуск и обновление кода.
- Каждая операция записывается в транзакции с `synchronous=FULL`. При остановке (SIGTERM во время редеплоя) сервер дожидается текущих запросов и корректно закрывает базу.
- Если сервис запущен на Railway без Volume или `DATA_DIR` указывает мимо Volume, приложение **не запустится** и напишет причину в лог.
- Автоматические резервные копии: раз в сутки в `DATA_DIR/backups/`, хранятся последние 14.
- Ручная копия: «Профиль» → «Резервная копия базы». Её стоит иногда скачивать к себе, так как Volume не защищает от удаления самого сервиса.
- Удаление сотрудника «мягкое»: он больше не может войти, оклад перестаёт начисляться, а его поступления и выплаты остаются в статистике.
- Оставляйте **одну реплику** сервиса: Volume подключается только к одному экземпляру, а SQLite рассчитан на одного писателя.

### Восстановление из копии

1. Остановите запись: в Railway временно уберите домен или предупредите сотрудников.
2. Через Railway CLI откройте shell сервиса: `railway ssh`.
3. Замените базу копией:

```bash
cp /data/backups/app-<дата>.db /data/app.db && rm -f /data/app.db-wal /data/app.db-shm
```

4. Перезапустите сервис (**Restart** в Railway).

Скачанную вручную копию можно открыть любым просмотрщиком SQLite (например, DB Browser for SQLite).

### Забыли пароль администратора

Задайте переменные `ADMIN_LOGIN` (существующий логин), `ADMIN_PASSWORD` (новый пароль) и `ADMIN_RESET_PASSWORD=1`, дождитесь перезапуска, войдите, затем **удалите** `ADMIN_RESET_PASSWORD`.

## Структура проекта

```
server/            сервер (Express)
  index.js         запуск, раздача клиента, healthcheck, корректная остановка
  config.js        переменные окружения, проверка Volume
  db.js            подключение SQLite и миграции
  auth.js          пароли, сессии, создание первого админа
  api.js           маршруты API приложения
  ext.js           API для расширения (вход по токену) и архив расширения
  payroll.js       зарплата: дневной оклад, % от поступлений, баланс
  analytics.js     аналитика: по часам, лучшее окно, прогноз, живая доска
  events.js        запись поступлений прибыли, уведомление о цели
  time.js          дни и часы в рабочем часовом поясе
  settings.js      настройки компании
  backup.js        автоматические резервные копии
client/            интерфейс (React + Vite)
extension/         расширение для Chrome (Manifest V3)
Dockerfile         сборка образа
railway.toml       настройки Railway (Dockerfile, healthcheck, 1 реплика)
```
